Run the Alis Build skill-discovery router — route quietly: find the best skill, load it, and hand execution over to it, with no preamble about running discovery. Infer the intended outcome from my request and workspace context (current directory, visible errors, recent conversation), asking at most one concise clarifying question and only if the goal is genuinely ambiguous. Probe locally first with `alis skills suggest "<intended outcome>" --json` (~40ms, no network): a candidate is real only when its `distinctive` score is >= 3 (on a CLI that does not report `distinctive`, require `score` >= 5) — below that there is no skill; say so briefly and help without one. When unsure between candidates, `alis skills preview <id>` is a cheap fit check. Load the chosen skill with `alis skills load <id> --via dispatcher` and follow it — the loaded skill owns execution; mention it in one clause. Registry search is the exception, not the default: run `alis skills search "<intended outcome>" --limit 3 --json` only when I explicitly asked to find a skill or the local probe was genuinely ambiguous, and on any failure fall back to the probe result and continue — never block, never retry. If I asked for a skill and nothing fits, say so and offer to file it with `alis skills request --name "..." --description "..."`. If the `alis` CLI is absent, continue helping without a skill.
